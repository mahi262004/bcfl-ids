# Measured results

Generated by `experiments/write_results.py` from `artifacts/results`. Do not edit by hand.

## Setup

- **Data:** N-BaIoT, all 7,062,606 rows converted, row counts checked against the published table. One federated client per device.
- **Task:** 11 classes (benign and 10 botnet attack families).
- **Split:** chronological within every source file: train 0-68%, validation 70-78%, test 80-100%, with gaps so sliding-window features cannot overlap.
- **Grid:** 444 runs, 3 seeds, 20 rounds, 5% stratified training sample, tested on all 1,412,554 held-out test rows.
- **Model:** MLP 115-128-64-11, Adam, learning rate 0.003, batch 256, 1 local epoch.
- **No tuning on test data:** thresholds and training settings were chosen on the validation split with seeds 101 and 102.
- **Attackers:** a random set of clients per seed. Headline metrics use honest devices only.

## Gate calibration (validation split)

Across 270 honest client-rounds, cosine to the median ranged from 0.292 to 0.894 and the norm ratio from 0.666 to 1.349. The chosen limits are cosine at least 0.1 and norm ratio at most 2.

## Explanations

- **Baseline check:** the mean of all traffic is itself classified as mirai_udpplain, so it is a poor reference. Explanations use mean benign traffic, classified as benign.
- **Completeness:** median relative error 0.082%. This confirms the integration is implemented correctly; it says nothing about faithfulness.
- **Deletion:** removing the top 10 features removes 94% of the evidence and flips 100% of decisions, against 9% and 5% for 10 random features.
- **Untrained-model sanity check:** rank correlation 0.30 with explanations from a randomly initialised model.
- **Stability across seeds:** rank correlations 0.92, 0.90, 0.93; top-20 overlap 95%, 90%, 85%.

## Limits

- Attack versus benign is easy on this dataset: a depth-3 decision tree already reaches about 99.8%. Robustness under attack is the meaningful result, not that number.
- The defence is built for up to 3 attackers of 9. With 4, it breaks under some attacks: macro F1 falls to about 0.05 (adaptive), 0.17 (Fang) and 0.01 (statistics poisoning), and for the first two that is worse than no defence.
- The adaptive attacker is the hardest case within the limit: it passes the gate every time, macro F1 falls to about 0.60 and the worst device's benign recall to about 0.77. A plain coordinate median does better against it (0.64).
- Reputation adds no measurable accuracy over the gate alone. Its value here is the audit trail.
- The gate's size check was changed after the first full run exposed a flaw against Min-Max. The fix was chosen on validation data, but it was prompted by test results, which is a mild selection effect.
- Two pairs of attack families (gafgyt tcp/udp, gafgyt junk/combo) are close to indistinguishable on later traffic with these features, even for a pooled random forest, which caps macro F1.
- Results come from one dataset, captured in 2018. Nothing here shows the model works on other networks or newer malware. No physical device was tested.
- All attackers are simulated and all traffic is replayed from the dataset. No real malware was used.
- The grid trains on a 5% stratified sample of the training rows and tests on all held-out rows. The deployed model uses 30%. Three seeds per setting.
- The chain is a single local Hardhat node, and the server is the only oracle. This makes verdicts tamper-evident after the fact; it does not decentralise the scoring.
- Raw traffic stays on the device, but feature statistics and plain model updates reach the server. There is no secure aggregation or differential privacy.
- Zero-knowledge verification is not implemented.

## Differences from the Dissertation-I report

The numbers above replace those in the Dissertation-I report (October 2026). They were produced by the code in this repository, and they differ for these reasons:

- 11-class detection, where the report used binary labels.
- Chronological split, where the report used a random stratified split.
- Cosine limit 0.1, where the report used -0.1, chosen from a new calibration on validation data.
- Norm ratio measured against the median update size, where the report used the norm of the median update. The first full run of this grid showed the report's form lets Min-Max attackers get honest updates rejected. The fix was chosen on validation data and the affected runs were repeated, but it was prompted by test results, which is a mild selection effect.
- Mean benign traffic as the explanation baseline, where the report used the mean of all traffic.
- Random attacker sets per seed, where the report fixed devices 4, 1 and 6.
- Added attacks: scaling, targeted evasion, LIE, Min-Max, Fang, statistics poisoning. Added defences for comparison: median, Multi-Krum, and each layer separately.
